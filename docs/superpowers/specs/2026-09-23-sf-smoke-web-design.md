# 顺丰 MCP 冒烟测试网页设计

## 目标

在现有 Python MCP 项目旁增加一个临时本机网页，用可视化表单验证顺丰下单与查件的请求和响应。网页用于开发与沙盒联调，不作为面向公网的业务系统。现有 MCP 工具与业务模型继续作为唯一的顺丰调用实现。

## 方案

使用 Python 标准库 HTTP 服务绑定 `127.0.0.1`，默认端口 `8765`。服务提供静态 `GET /`、不含密钥的 `GET /api/status`，以及 `POST /api/order`、`POST /api/track`。两个 POST 复用 `CreateOrderInput`、`TrackInput`、`create_order`、`track_shipment` 和 `SfApiClient`。只接受 JSON 请求，限制请求体大小，不设置跨域许可。下单接口独立检查 `SF_ENV=sandbox`，即使生产下单开关已开启也拒绝通过网页下生产单。

## 页面

单页分为“创建订单”和“查询物流”两块。创建订单表单覆盖客户订单号、寄收件人姓名/手机号/省市区/详细地址、托寄物名称与数量、付款方式、是否通知揽收。提交前显示完整订单摘要，由操作者确认。查件表单支持运单号与客户订单号。结果区展示状态、错误码、运单号和按时间排序的轨迹；另有可折叠原始结构化结果便于排查。页面不使用本地存储、Cookie 或第三方前端依赖，也不显示校验码。

## 安全与错误

- `GET /api/status` 只返回当前环境及凭据是否已配置的布尔值，不返回任何凭据。
- 只监听本机回环地址；POST 校验 `Content-Type: application/json`、同源 `Origin`（若存在）及请求体大小。
- 无凭据、非沙盒下单、输入错误和顺丰业务错误显示清楚的状态与错误码；不在错误中回显寄收件人完整资料。
- 后端不保存订单、手机号、地址或密钥。浏览器刷新会清空输入。

## 验证与交付

交付 `smoke_web.py`、静态 HTML/CSS/JS、启动命令与 README 说明。自动测试覆盖状态接口、输入校验、只允许沙盒下单及查件请求映射；本机浏览器检查页面布局和交互。没有顺丰凭据时，仅验证本地流程和模拟响应；取得沙盒权限后再实际下单和查件。
